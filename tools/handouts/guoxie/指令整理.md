# 國寫素材庫｜指令整理

本檔整理兩種「指令」：
**一、需求指令**——這本書是依哪些要求做出來的（可直接複製，下次請 AI 製作其他科目或其他主題時沿用）；
**二、操作指令**——如何在電腦上重新排版、修改內容、增加單元。

---

## 一、需求指令彙整

### 1. 製作過程中下達的指令（依時間順序）

| # | 指令原文 | 落實方式 |
| --- | --- | --- |
| 1 | 整理一份國文的作文整理，包括仿寫、替代詞、成語、名言、典故等等整理，網路搜集 | 分 12 個單元：國寫速覽、仿寫（上、下）、替代詞、成語（主題分類／易誤用易寫錯）、名言（古典／現代與外國）、典故與人物事例（古代／近現代）、詩詞名句、易錯字標點語病；每條素材上網查證，來源列在書末 |
| 2 | 古典經籍風格的優雅排版 | 曾做成明體加楷體、朱印標籤、線裝封面的版本；後來依第 3 項改版 |
| 3 | （上傳《科學班國文歷屆試題詳解集｜指令整理》）用這格式 | 改用同一套格式：全書芫荽字體、彩色螢光筆與筆記框、封面、編輯說明（資料來源）、使用說明（記號圖例）、可點選且有頁碼的目錄、各部總覽頁、解答篇、書末附錄（答案速查、細目索引、資料來源），並交付本檔與可重新排版的原始檔 |
| 4 | 還是太有 AI 教學感了，繼續潤飾 | 全書說明文字改為參考書語體：不對讀者喊話、不寫導覽式開場、不替例句寫賞析、不用格言與對句、不湊三點、不用口語；固定用語統一為「作用／適用／不宜／注意／句型／示例」。細則見 `STYLE.md` |

### 2. 可重複使用的完整指令（Prompt）

把下面整段貼給 AI 即可。〔 〕內換成自己的內容。

```text
請製作一本「〔學測國寫素材庫〕」，輸出為 A4 的 PDF。

【內容】
- 給〔準備學測國語文寫作能力測驗的高中生〕用，整理寫作文可以用的素材：
  〔仿寫句式、替代詞、成語（主題分類、易誤用與易寫錯）、名言（古典、現代與外國）、
  典故與人物事例（古代、近現代）、詩詞名句、易錯字、標點與常見語病〕。
- 每一類素材都要說明：適合用在哪一種題目、一篇用多少、常見的誤用；並附可以仿寫的示範句。
- 每個單元附練習題，解答與說明放在書末。

【蒐集與查證】
- 素材從網路蒐集，但每一條都要上網查證後才收，並記下查證的網址。
- 成語的寫法、釋義、出處以教育部《成語典》《重編國語辭典修訂本》為準；辭典沒有標明典源的，出處留空。
- 古典名句與詩詞逐句對原文；有異文的採臺灣高中課本與通行寫法，並註明「一作……」。
- 現代與外國名言只收查得到可靠出處的；查不到或有爭議的一律不收，或列入「常被引錯」的表。
- 人物事例的年代、數字要查證，不確定的細節不寫。
- 不收歷屆試題的官方參考答案、評分原則與考生佳作，不收他人已發表的範文。
- 解釋、白話、例句都重新撰寫，不照抄網頁；沒有把握的出處、年代、作者寧可不寫，不可杜撰。
- 使用臺灣繁體中文與臺灣用語。

【文風】
- 讀起來要像市售的國文參考書：條目化、客觀、精煉、有術語。
- 不對讀者喊話（不用「你」「我們」、不用勸導的祈使句），不寫導覽式的開場白，不替例句寫賞析，
  不用格言與對句，不用「不是……而是……」，不用比喻說理，不刻意湊三點，不口語。
- 固定用語：作用、適用、不宜、注意、句型、示例、辨析、補充。

【審稿】
- 每個單元寫完後，由另一位審稿者獨立複查：重新上網核對字句與出處、自己先做一遍練習再對答案、
  檢查選擇題答案是否平均分布、示範句是否自然。

【每本書都要有】
- 封面、編輯說明（資料來源與查證原則）、使用說明（記號圖例）、可點選且有頁碼的目錄、
  各部的章名頁與單元總覽、解答篇、書末附錄（選擇題答案速查、細目索引附頁碼、資料來源）。

【版面】
- 非常精美、編排細節清楚；全書字體使用「芫荽（Iansui）」。
- 像畫過重點的筆記：重點詞用螢光筆、要注意的地方用紅色波浪線；
  規則放「重點整理」框、補充知識放便利貼樣式的「延伸補充」、常見錯誤放紅色虛線的「易錯提醒」。
- 各部用不同的代表色；單元題頭顯示單元代號、標題與所屬的部。

【交付】
- PDF。
- 一份「指令整理.md」：整理我下過的需求指令（含這份 prompt），以及重新排版、修改內容、增加單元的操作指令。
- 可重新排版的原始檔（內容檔、排版程式、樣式）。
```

### 3. 內容品質規範

撰寫每個單元時遵守的細則（可用的標籤、查證規則、寫作規則）寫在 [`FORMAT.md`](FORMAT.md)；文風規範（含改寫前後的對照）寫在 [`STYLE.md`](STYLE.md)。

## 二、操作指令

### 0. 專案結構

```
guoxie/
├── content/            各單元內容檔（N1.body.html、N1.ans.html …）← 要改內容就改這裡
├── sources/            各單元查證過的網址（N2.sources.json …）
├── build.mjs           內容檔 → PDF 的排版程式（封面、編輯說明、使用說明、目錄、總覽、附錄都在這裡）
├── base.css            基礎樣式（框、表格、練習題的結構）
├── theme.css           筆記版樣式（字體、顏色、螢光筆、筆記框）
├── join.py             把封面接到本文前面（保留目錄的超連結）
├── tools/check.py      檢查單一單元的格式
├── tools/sources.py    由 sources/ 重新產生書末的〈資料來源〉
├── FORMAT.md           內容檔格式與品質規範
├── STYLE.md            文風規範（參考書語體）
└── dist/國寫素材庫.pdf   ← 成品
```

### 1. 環境準備（只需一次）

需要 Node.js、Python 3（含 `pypdf`）與 poppler-utils（`pdftotext`、`pdfinfo`）。

```bash
cd guoxie
```

```bash
npm install
```

```bash
npx playwright install chromium
```

```bash
pip3 install pypdf
```

macOS 安裝 poppler：

```bash
brew install poppler
```

### 2. 產生全書 PDF

```bash
node build.mjs
```

- 會自動排版多次：先排一次取得各單元與各節的頁碼，回填目錄、總覽頁與細目索引後再排，直到頁碼不再變動。
- 成品：`dist/國寫素材庫.pdf`。
- 結尾顯示「頁數一致 ✓」表示目錄頁碼正確。

### 3. 只排某幾個單元（改稿時用）

```bash
python3 tools/check.py N5
```

檢查 N5 的內容檔：標籤與 class、題號與解答是否對得上、有沒有不該出現的用語。印出 `OK` 才算通過。

```bash
node build.mjs N5,N6
```

只排 N5、N6，輸出樣張 `dist/sample.pdf`（沒有封面、目錄與附錄）。

### 4. 修改內容

所有文字都在 `content/單元代號.body.html`（本文）與 `content/單元代號.ans.html`（解答），用純文字編輯器即可修改。最常用的寫法：

| 想做的事 | 寫法 |
| --- | --- |
| 黃色螢光筆 | `<strong>文字</strong>` |
| 紅色波浪線 | `<em>文字</em>` |
| 示範句＋藍色小字說明 | `<p class="eg"><span class="en">句子</span><span class="zh">說明</span></p>` |
| 重點整理框 | `<div class="key"><p>…</p></div>` |
| 便利貼（延伸補充） | `<div class="tip"><p>…</p></div>` |
| 紅色虛線框（易錯提醒） | `<div class="warn"><p>…</p></div>` |
| 誤／正對照 | `<p class="bad"><span class="mark">誤</span>…</p>`、`<p class="good"><span class="mark">正</span>…</p>` |
| 表格 | `<table class="t"><thead><tr><th>欄1</th><th>欄2</th></tr></thead><tbody><tr><td>…</td><td>…</td></tr></tbody></table>` |

完整說明見 [`FORMAT.md`](FORMAT.md)。改完後依序執行第 3、第 2 節的指令。

若改了 `sources/` 裡的來源檔，先重新產生〈資料來源〉再排版：

```bash
python3 tools/sources.py
```

### 5. 調整版面

| 想調整 | 修改位置 |
| --- | --- |
| 字體 | `theme.css` 最上方 `:root` 的 `--hand`（目前為 Iansui，缺字時以霞鶩文楷 TC 補） |
| 螢光筆、紅筆、藍筆的顏色 | `theme.css` 的 `:root`（`--hl`、`--red`、`--blue`、`--green`） |
| 各部的代表色 | `build.mjs` 最上方的 `COL` |
| 紙張邊界、內文字級 | `theme.css` 的 `@page` 與 `html { font-size }` |
| 三種筆記框的名稱與樣式 | `theme.css` 的 `.key`、`.tip`、`.warn` |
| 封面文字 | `build.mjs` 的 `coverHtml()` |
| 編輯說明、使用說明 | `build.mjs` 的 `frontHtml()` |
| 各單元在總覽頁的一句話介紹 | `build.mjs` 的 `DESC` |

若想換成別的字體，把 `--hand` 改成該字體名稱，並在 `build.mjs` 的 `fontCss` 清單加入對應的字體 CSS。

### 6. 新增單元（例如 N13）

1. 依 `FORMAT.md` 撰寫 `content/N13.body.html` 與 `content/N13.ans.html`（可把 `FORMAT.md` 和一個現有單元交給 AI 當範例），查證的網址記在 `sources/N13.sources.json`。
2. 在 `build.mjs` 的 `PARTDEF` 把 `'N13'` 加進要放的那一部，並在 `DESC` 加一句介紹；`tools/sources.py` 的 `NAME` 也加上單元名稱。
3. 執行第 3 節的檢查與樣張，再執行第 2 節。目錄、總覽頁、答案速查、細目索引會自動更新。

### 7. 常見問題

| 狀況 | 處理 |
| --- | --- |
| `check.py` 顯示「不允許的 class」或「標籤不成對」 | 依訊息的行號修正；只能用 `FORMAT.md` 列出的標籤與 class |
| 顯示「解答缺」「解答多出」 | 本文的題號（`id="N5-01"`）和解答檔的題號要一一對應 |
| 某個字顯示成不同字體 | 芫荽缺該字，已自動以霞鶩文楷補字；屬正常現象 |
| 結尾顯示「頁數不一致」 | 再執行一次 `node build.mjs` |
| 表格第一欄被擠成兩行 | 第一欄文字在 7 個字以內會自動不換行；較長的請縮短，或減少該表的欄數 |
| 答案速查表少了某一題 | 該題解答沒有寫成「題號後面接 `(B)`」的格式 |
