## 0. 決策摘要

1. **數A、數B 一起做**。兩科結構相同（20 題、85＋15 分、100 分鐘），差別只在範圍與配分（單選 6 vs 7 題、多選 6 vs 5 題）；同一套元件和批改程式即可，資料已經兩科都備齊（P1）。
2. **公式一律存 LaTeX，網頁用 KaTeX 排版**（§3）。KaTeX 以獨立 chunk 延遲載入，只在數學頁面下載：JS 277 KB／gzip 76 KB、CSS 23 KB，字型 20 個 woff2 共 254 KB 依需要載入（實測，katex 0.16.22）。資料層已用 KaTeX 實際排版過全部 2,010 段公式（validator `--katex`）。
3. **選填題用「仿答題卷」的格子輸入**（§4.3）：題目旁顯示官方格式（例如 $\frac{\square\sqrt{\square}}{\square}$），每一格點選 0–9、−、±；批改＝每格全對（§5）。這是唯一和官方計分完全一致的作法，也避免「4/2 和 2 算不算對」的爭議。
4. **自動批改只做選擇與選填**；非選擇題（每卷 10–12 分）不自動給分：作答後顯示本站詳解讓學生自評，P5 再考慮拍照上傳、AI 回饋（扣點）。成績單分開顯示「自動批改分數（滿分 88，111 數B 為 90）」與「非選擇題自評」。
5. **詳解全部自寫，並由獨立的第二次解題驗算**（§6）。生成時不給模型任何官方解答或評分原則；選擇（填）題的最終答案必須同時符合官方答案與獨立解題結果，非選擇題的最終數值要兩次獨立解題一致，並用 SymPy 驗算數值；不一致的進人工佇列。詳解另存檔，不寫進歷屆試題 JSON。
6. **PDF 公式用建置時預先渲染的 SVG**（§7.2）：pdfmake 不會排版 LaTeX；在 `build-data` 階段用 MathJax（node）把每段公式轉成 SVG（實測中等長度公式約 7 KB），PDF 引擎以 `svg` 節點嵌入。網頁仍用 KaTeX。
7. **分五期**：P1 資料（完成）→ P2 歷屆試題＋詳解 → P3 模擬考＋PDF → P4 AI 題庫（單元×難度）→ P5 學習助手數學版＋講義（§1）。

## 3. 公式渲染

### 3.1 網頁：KaTeX

- **相依**：`katex@0.16.x`（MIT）。只在數學路由用 `import()` 延遲載入；CSS 隨 chunk 載入；字型由 CSS 的 `@font-face` 依需要下載（題目常用 Main、Math-Italic、Size1–2、AMS，估計首頁面約 60–100 KB（估計））。英文頁面完全不受影響。
- **元件**：`<MathText text="…$…$…" />`：把字串切成文字與 `$…$` 片段，公式用 `katex.renderToString(tex, {throwOnError:false, output:'htmlAndMathml', strict:'ignore'})`；`htmlAndMathml` 讓螢幕報讀可以讀 MathML。結果以 `useMemo` 快取。排版失敗（理論上 validator 已擋）顯示原始 LaTeX 並回報錯誤。
- **預先渲染（選配）**：歷屆題是靜態資料，可以在 `build-data` 時就用 KaTeX 產生 HTML 字串，前端只載 CSS 與字型、不載 KaTeX JS。學習助手與 AI 題庫的即時內容仍需要 JS，所以第一版先全部在前端排版，量到首屏太慢再改。
- **排版細節**：長公式（例如標準差公式、增廣矩陣）在 320 px 會超寬：公式容器 `overflow-x:auto`，不讓整頁水平捲動；矩陣與分數的行高要預留（`line-height` 不可太小，否則上下重疊）；深色模式下 KaTeX 用 `currentColor`，不用另外處理。
- **巨集**：資料已統一寫法（`\overrightarrow`、`\overline`、`bmatrix`、`cases`…，見格式文件），不需要自訂巨集；AI 產出若用到 KaTeX 不支援的指令，由 §8 的檢查擋下。

### 3.2 圖與表

- 圖是 PNG（16 階灰階，從官方 PDF 裁切），`<img alt=…>` 用 JSON 的 `alt`；寬度 `max-width:100%`，點擊放大。
- 表格用 HTML table，儲存格內容同樣經 `MathText`；`note` 顯示在表下。
- 選項是圖（112 數B 第 1 題）時，選項按鈕內放圖，按鈕的 `aria-label` 用 alt。

## 4. 作答介面

### 4.1 單選、多選

沿用英文的選項元件；多選題改成核取方塊外觀，題號旁標「多選」。選項代號顯示 (1)–(5)（官方格式），答案以數字字串存。

### 4.2 題組與混合題

題組文字（含圖、表）固定在上方，手機版可收合；小題逐一顯示。非選擇題小題顯示「非選擇題（6 分）：請在紙上作答，完成後看詳解自評」，P2 不提供線上書寫框（數學式在手機上打字不實際）。

### 4.3 選填題

- 題幹中 `[[FILL]]` 的位置顯示 template 排版後的格式，每一格是一個可點的方框（顯示格號 13-1、13-2…）。點選格子後，下方出現一列鍵盤：`1 2 3 4 5 6 7 8 9 0 − ±`，和答題卷劃記列相同；選完自動跳下一格；可清除。實體鍵盤可直接打數字與減號。
- 作答中即時以 KaTeX 預覽「你的答案」（例如 $\frac{9}{10}$），讓學生確認格式（例如帶分數、根號位置）。
- 無障礙：每一格是 `role="spinbutton"` 或 `<select>` 的替代（螢幕報讀唸「13-2 格，目前 1」）。
- 實作：template 以 KaTeX 排版，格子先以 `\boxed{\phantom{0}}` 佔位，再用 `\htmlId`（KaTeX `trust` 選項只允許 `htmlId`）定位覆蓋可點的按鈕；若定位在 iOS 不穩，退回「template 預覽＋下方一排格子輸入」的雙列版面（未驗證，P2 原型決定）。

## 5. 批改規則

| 題型 | 規則（與題本封面一致） |
|---|---|
| 單選 | 答案相同得全分，否則 0（含未答） |
| 多選 | n 個選項（目前都是 5）逐一判定；全未作答得 0；答錯 k 個（該選未選、不該選卻選，都算錯）得 `points × (n − 2k) / n`，低於 0 以 0 計。例：5 分題錯 1 個得 3 分、錯 2 個得 1 分 |

## 6. 詳解（P2）

### 6.1 原則

- **D8**：生成與驗算時都不提供官方參考答案、評分原則、試題解析或電子報解說，也不讓模型「回想」官方解答；提示詞明確禁止引用。選擇（填）題的官方答案代號只在**驗算比對**時由程式使用，不放進生成提示。
- 詳解是本站著作，標示「本站詳解（AI 撰寫・已獨立驗算）」，經人工審核者另標「已審核」。
- 內容結構：考點（對應單元）、關鍵觀察、逐步解法（每步一行公式＋一句說明）、答案、常見錯誤（對應錯誤選項或格式陷阱）、延伸（可選）。混合題組的非選擇題詳解要寫出完整推導（學生用來自評）。

### 6.2 管線（離線，CI 或本機腳本，不在使用者請求時跑）

1. **生成**：輸入題目 JSON（題幹、選項、圖的 alt 與圖片、表），由預設模型寫詳解（結構化輸出：`steps[]`、`final_answer`）。
2. **獨立解題**：另一次呼叫，只給題目、不給詳解，請它解出最終答案（選擇題代號、選填各格、非選擇題的數值或式子）。
3. **自動比對**：
   - 選擇／選填：生成的 `final_answer`、獨立解題答案、官方答案三者一致才算通過。
   - 非選擇題：兩次的最終數值／式子一致（用 SymPy 化簡後比較：`simplify(a - b) == 0`，向量逐分量、區間比端點），並把詳解中的關鍵等式交給 SymPy 抽查。
   - 格式：所有公式能被 KaTeX 排版；不含禁止字詞（官方機構名稱、「評分原則」字樣）。
4. **不一致**：重試一次（換種子提示）；仍不一致進人工佇列，網站對該題暫不顯示詳解。
5. **人工審核**：P2 上線前至少抽審 20%＋全部難題（官方答對率 < 30% 的題目）；審核結果記錄在詳解檔（誰、何時、結論）。

### 6.3 存放

`data/exams/solutions-math/{id}.json`：`{ "id", "items": { "13": { "steps": [...], "final_answer": ..., "verification": { "independent": "...", "sympy": "pass", "official_match": true }, "review": { "status": "approved|pending", "by": "...", "at": "..." }, "generated_at": "..." } } }`。與歷屆題分開，方便重產與下架（沿用 `data/unpublish.jsonl` 機制）。

### 6.4 成本（估計）

200 題 ×（生成約 3k 輸出 token＋獨立解題約 1.5k＋重試 15%）。具體金額依目前預設模型價目表在 P2 開工時估算並寫進工作包；不影響使用者點數（離線產生）。

## 7. 模擬考與 PDF（P3）

### 7.1 模擬考

- 歷屆整卷：100 分鐘計時、可暫停（練習模式）或不可暫停（實考模式），沿用英文模擬考的作答頁與成績單框架，題目元件換成數學版。
- 成績單：各大題得分、每題對錯、全國答對率（官方統計）、單元雷達圖（依 `tags.units`）、錯題連到詳解與同單元題目。

### 7.2 PDF

- 引擎沿用 `renderExamPdf`（pdfmake 0.3.11）。pdfmake 沒有 LaTeX 排版能力，所以：
  - 在 `build-data` 用 `mathjax-full`（node，Apache-2.0）把每段 `$…$` 轉成獨立 SVG（`fontCache:'none'`），存成 `public/data/math/svg/{id}.json`（公式字串雜湊 → SVG）。實測中等長度公式（分數＋根號＋2×2 矩陣＋向量）約 7 KB；一卷估計 200–400 KB（估計），只在下載 PDF 時抓。
  - PDF 中行內公式以 pdfmake `svg` 節點嵌入，依 MathJax 回報的 `ex` 高度與基線對齊（未驗證 pdfmake 0.3 的行內 SVG 基線處理；P3 先做原型，不行就把含公式的句子整段排成「文字＋SVG」的 columns）。
  - 替代方案：瀏覽器列印（`window.print()`＋列印 CSS，公式用 KaTeX）。實作簡單，但各手機瀏覽器的列印與存 PDF 行為不一，英文版已選擇 pdfmake，數學版維持一致（§12 問題 8）。
- 學生卷附「仿官方答題卷」：選擇題劃記列、選填題 0–9／−／± 劃記格、第貳部分作答區（作圖題附坐標格）。版面參考官方答題卷 PDF 的**格式**（不含任何評分內容）。
- 教師卷：答案、選填各格、本站詳解。
- 字型：中文沿用英文版的字型子集流程；公式在 SVG 內，不需要數學字型。

## 8. AI 題庫（P4）

### 8.1 出題規格

- 由 111–115 結構化資料歸納：各考科題型配置（§研究 3.2）、單元分布（§研究 4）、情境類型、選填格式種類（分數、根式、小數、比、坐標、方程式）。輸出 `data/exams/generation-spec-math.json`（比照英文 `generation-spec.json`）。
- 抽題軸：考科（A／B）× 單元（21 個標籤；數B 不出 `space_line_plane`、`linear_system`，數A 不出 `conics`、`data_modeling` 專屬題）× 難度（3 級）× 題型。

### 8.2 難度校準

- 官方答對率（P）與鑑別度（D）併入後，以歷屆題建立「題目特徵 → P」的對照（題型、步驟數、單元數、是否需要圖表），定義三級：穩定基礎（預期 P ≥ 60%）、進階練習（30–60%）、超越頂標（< 30%）（設計值，上線後依作答資料校正）。
- AI 題目先由模型自評難度，再由獨立解題的步驟數與錯誤率修正；上線後用本站作答資料（答對率）回饋。

### 8.3 驗算（與 §6 共用）

每題：兩次獨立解題答案一致＋SymPy 驗算＋選項唯一性檢查（單選只有一個對、多選各選項真假明確）＋選填答案可用格子表示（位數、負號、最簡分數／根式）＋KaTeX 可排版＋與歷屆題相似度檢查（文字與數值都不可近似）。

### 8.4 圖

不用影像生成模型。圖用宣告式 JSON（坐標軸、點、線段、圓、函數圖形、立體示意的頂點與稜）由程式畫成 SVG，資料與數學內容一致、可驗算；`alt` 由同一份 JSON 自動產生後再潤飾。

## 11. 風險

| 風險 | 影響 | 對策 |
|---|---|---|
| 公式轉錄錯誤（Word 版與 PDF 不一致） | 學生看到錯題 | P1 已逐頁看圖並修正 9 處；P2 上線前請一位數學老師快速核對 200 題（todo）；網站提供「回報題目錯誤」 |
| AI 詳解錯誤 | 最大的信任風險 | 獨立驗算＋官方答案比對＋SymPy＋人工抽審；未通過不顯示 |
| 選填輸入在手機難用 | 作答體驗 | P2 先做原型，實機測試 iOS Safari／Android Chrome |
| KaTeX 首次載入變慢 | 首屏時間 | 延遲載入、只在數學路由；必要時改建置時預渲染 |
| PDF 公式基線不齊、SVG 太大 | PDF 品質與下載時間 | P3 原型先驗證；每卷 SVG 預估 200–400 KB，只在下載時抓 |
| 非選擇題無法自動批改 | 分數不完整 | 分開顯示、自評；P5 再評估 AI 回饋 |
| 數A／數B 範圍誤標 | AI 題目超出範圍 | 單元標籤依考試說明附件一；出題規格限制各科可用單元 |

## 14. P2 實作備註（2026-11-06，網頁模組）

和前面各節不同、或前面沒寫到的做法（以這裡為準）：

1. **檔案**：共用型別與批改 `packages/shared/src/math-exam.ts`（`gradeSingle`／`gradeMulti`／`gradeFill`、`scoreMathPaper`、`splitMathStem`、`parseFillTemplate`）；資料輸出 `apps/web/scripts/lib/math-data.mjs`（`math/index.json`、`math/{id}.json`、`math/solutions/{id}.json`、`math/figures/{id}/*.png`）；前端 `apps/web/src/data/math.ts`、`apps/web/src/features/math/`。
2. **路由**：`/math`（數A／數B 分頁，網址 `?subject=b`；有 `era: "舊課綱"` 的卷子時自動多一個「舊課綱」分頁）、`/math/:paperId`（練習模式／考試模式）、`/math/:paperId/results`（成績與詳解）。側邊欄多一個「數學」群組；首頁卡片與手機「更多」面板跟著 `modules.ts` 自動列出。
3. **課綱**：卷子的 `era` 由資料的 `era` 欄位決定，沒有時依 `subject`（`math_a`／`math_b`＝108課綱，`math`＝舊課綱）。100–110 的舊課綱卷子放進 `data/exams/parsed-math/gsat-math-{year}.json` 就會出現，不必改程式（多選題的 5／3／1／0 級距在 5 分題、5 個選項時與 (n−2k)/n 相同）。
4. **詳解**：`data/exams/math-solutions/{id}.json` 由另一條流程產生，格式寬鬆接受（陣列、`{items:[…]}`、`{items:{題號:{…}}}`；每題 `no`、`solution_md`、`unit`、`difficulty`、`answer_display`、`check`、`flags`）。沒有檔案或沒有那一題時顯示「詳解準備中」；`flags` 含 `withhold`／`reject`／`mismatch` 等、或文字含機構名稱或「評分原則」的題目不輸出。`check` 通過時標「AI 撰寫・已獨立驗算」。詳解在看答案或交卷後才下載。
5. **選填輸入**：§4.3 的「`\htmlId` 覆蓋按鈕」沒有做，採用文件裡的退路：題幹的 `[[FILL]]` 位置畫空方框，下方 KaTeX 排「作答格式」（每格標格號）與即時的「你的答案」，每一格一列 12 個劃記（原生 radio，透明蓋滿圓圈；手機兩排各 6 顆、36px）。焦點在某一列時直接按數字或減號就劃記並跳到下一列，Backspace 清除。
6. **KaTeX**：`import('katex')`＋CSS 獨立 chunk（JS 259 KB／gzip 77.5 KB、CSS 28.8 KB），只在卷子頁與成績頁載入；入口頁不載（e2e 驗）。用 `katex.render` 排進 `<span>`（不經 innerHTML，`source-scan.test.ts` 的規則）。主程式 352.32 → 353.72 KB（gzip 112.92 → 113.40），增加的只有路由與模組清單。
7. **非選擇題**：卷子頁顯示紙上作答說明與「拍照 AI 批改即將推出」（不是按鈕、不呼叫 API）；成績頁可以自評 0～配分（存在本機 `gsat-math-self:v1:{id}`），自評合計另列，不混進自動批改分數。作答紀錄存在 `gsat-math-attempt:v1:{id}`，沿用英文的 `AttemptStore`。
8. **出處**：頁尾與入口照英文歷屆試題寫「試題來源：大學入學考試中心…」（§12 問題 6 待站主確認）；其他文案一律「官方」，`features/math/copy.test.ts` 檢查。
9. **側邊欄高度**：多了「數學」群組（約 50px），1366×640 未登入與 1280×600 會出現淡出遮罩（`desktop-shell.spec.ts` 已改）；desktop-ui.md §16.5 的高度預算需要設計者重新決定。
10. **還沒做**：官方答對率併入 `item.stats`（前端已會顯示，資料待 P1 todo）；依單元篩題；混合題組文字在手機收合；PDF（P3）；級分估計（P3）。
